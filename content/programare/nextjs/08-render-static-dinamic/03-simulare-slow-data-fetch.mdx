Aplicația de tip dashboard pe care o construim este dinamică.

Cu toate acestea, rămâne problema menționată în capitolul anterior: **ce se întâmplă dacă o singură cerere de date este mai lentă decât toate celelalte?**

Hai să simulăm o încărcare lentă a datelor.
În `app/lib/data.ts`, decomentează liniile cu `console.log` și `setTimeout` din interiorul funcției `fetchRevenue()`:

```typescript
// /app/lib/data.ts
export async function fetchRevenue() {
  try {
    // Întârziem artificial răspunsul în scop demonstrativ.
    // Nu face asta în producție :)
    console.log('Fetching revenue data...');
    await new Promise((resolve) => setTimeout(resolve, 3000));

    const data = await sql<Revenue[]>`SELECT * FROM revenue`;

    console.log('Data fetch completed after 3 seconds.');

    return data;
  } catch (error) {
    console.error('Database Error:', error);
    throw new Error('Failed to fetch revenue data.');
  }
}
```

Acum deschide `http://localhost:3000/dashboard/` într-un tab nou și observă cum pagina durează mai mult să se încarce.
În terminalul tău ar trebui să vezi următoarele mesaje:

```text
Fetching revenue data...
Data fetch completed after 3 seconds.

```

Prin adăugarea acestei întârzieri artificiale de 3 secunde, întreaga pagină este acum blocată și nu poate afișa interfața (UI) vizitatorului în timp ce datele sunt preluate.

Acest lucru ne aduce la o provocare frecventă pe care dezvoltatorii trebuie să o rezolve:

> **În cazul rendării dinamice, aplicația ta este doar la fel de rapidă ca cea mai lentă preluare de date.**
