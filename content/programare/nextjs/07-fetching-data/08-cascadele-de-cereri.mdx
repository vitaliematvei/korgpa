O „cascadă” (_waterfall_) se referă la o secvență de cereri de rețea în care fiecare cerere depinde de finalizarea celei anterioare.
În cazul preluării datelor (_data fetching_), o cerere nouă poate începe doar după ce cererea precedentă a returnat deja rezultatul.

De exemplu, trebuie să așteptăm executarea funcției `fetchRevenue()` înainte de a putea începe rularea `fetchLatestInvoices()`, și așa mai departe:

```tsx
// /app/dashboard/page.tsx
const revenue = await fetchRevenue();
const latestInvoices = await fetchLatestInvoices(); // așteaptă finalizarea fetchRevenue()
const {
  numberOfInvoices,
  numberOfCustomers,
  totalPaidInvoices,
  totalPendingInvoices,
} = await fetchCardData(); // așteaptă finalizarea fetchLatestInvoices()
```

Acest tipar (_pattern_) nu este neapărat un lucru rău.
Pot exista situații în care o cascadă de cereri este intenționată, deoarece dorești ca o anumită condiție să fie îndeplinită înainte de a efectua următoarea cerere.
De exemplu, s-ar putea să vrei să preiei mai întâi ID-ul și profilul unui utilizator.
Odată ce ai obținut ID-ul, poți trece la preluarea listei sale de prieteni.
În acest caz, fiecare cerere depinde în mod direct de datele returnate de cererea anterioară.

Cu toate acestea, acest comportament poate fi uneori neintenționat și poate afecta negativ performanța aplicației.
