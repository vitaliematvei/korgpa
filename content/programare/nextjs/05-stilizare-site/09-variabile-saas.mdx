Am discutat scurt despre faptul că Sass este o metodă ceva mai de școală veche pentru stilizare, dar acesta oferă mult mai multe funcționalități decât CSS Modules.
Această funcționalitate ne permite să rulăm operații matematice de bază, cum ar fi adunarea valorilor, sau să folosim o comandă `lighten()` pentru a deschide o nuanță de culoare cu, să zicem, 10–20%.

O caracteristică extrem de utilă a Sass-ului sunt variabilele.
Pentru cei neinițiați, gândiți-vă la ele ca la niște containere (_placeholders_) pentru valori.
Definim un astfel de container la începutul codului nostru, atribuindu-i o valoare specifică, cum ar fi codul hexazecimal al unei culori.
Dacă folosim acea culoare oriunde în cod, vom apela valoarea containerului — iar dacă definiția originală se schimbă, Sass va înlocui automat fiecare instanță a acelui _placeholder_ cu valoarea actualizată.

Unul dintre lucrurile excelente la stilizarea în Next.js este că suportă exportarea variabilelor Sass din fișierele CSS Modules.
De exemplu, am putea face ceva de genul acesta, unde folosim variabila Sass exportată `primaryColor`:

```scss
/* variables.module.scss */
$primary-color: #64ff00;

:export {
  primaryColor: $primary-color;
}
```

Apoi am face legătura către acest fișier de variabile din `_app.js`:

```jsx
import variables from '../styles/variables.module.scss';

export default function MyApp({ Component, pageProps }) {
  return (
    <Layout color={variables.primaryColor}>
      <Component {...pageProps} />
    </Layout>
  );
}
```

Totuși, există o problemă critică: nu putem folosi această abordare pe site-ul nostru.
Am încercat această metodă pentru a stiliza subsolul (_Footer_), având scopul de a crea un fișier `variables.scss` care să conțină toate culorile pe care trebuia să le referențiem în site.
Pentru a realiza acest lucru (sau cel puțin pentru a încerca), am urmat acești pași:

1. Am creat un fișier nou numit `variables.module.scss` în directorul `\styles`.
2. Am adăugat acest cod ca punct de plecare:

```scss
/* color scheme */
$primary-black: #000000;

:export {
  primaryBlack: $primary-black;
}
```

3. Am modificat importurile în `Footer.jsx` astfel:

```jsx
import styles from "./Footer.module.css";
import variables from "../../styles/variables.scss";

<div className={styles.footerContainer} backgroundColor={variables.primaryBlack}>

```

Aici s-a blocat totul — la compilarea stilurilor, am primit următorul mesaj de eroare:

> `./styles/variables.scss`
> Global CSS cannot be imported from files other than your Custom `<App>`. Due to the Global nature of stylesheets, and to avoid conflicts, Please move all first-party global CSS imports to `pages/_app.js`. Or convert the import to Component-Level CSS (CSS Modules).
> Read more: [https://nextjs.org/docs/messages/css-global](https://nextjs.org/docs/messages/css-global)
> Location: `components\Footer\Footer.jsx`

Această abordare funcționează doar dacă facem referire la fișier din `_app.js` și dacă avem mai multe componente pe care le stilizăm _inline_, folosind o metodă CSS-in-JS. Nu este cazul nostru, așa că, din păcate, este o abordare pe care trebuie să o abandonăm pentru site-ul nostru, cel puțin deocamdată!
